Install guide

About 15 minutes. You run one installer on your server; it asks a few questions, explains each one, and can be run again at any time without losing anything.

What you need

A serverA computer that's always on, with Docker and Docker Compose: a Raspberry Pi 4 or 5, a NAS, a mini PC, a home server. Linux, macOS, or Windows (see below). Check with docker compose version.
Home AssistantOn the same network, with your devices assigned to areas (Settings → Areas). Areas become the rooms on the screen.
A screenOne of these:
  • A device that already runs KUAL. PaperKiosk installs a KUAL extension that shows the kiosk full screen. The USBNetwork extension is optional: with it, setup and updates also work over Wi-Fi.
  • Any browser: a tablet, an old phone, an e-reader's built-in browser.
  • Another e-paper dashboard or screenshot service that loads a URL.

PaperKiosk starts where KUAL already runs. Getting KUAL onto a device isn't part of this project and isn't covered here (see the FAQ).

On Windows

The installer is a Linux script. On Windows it runs in WSL (Windows Subsystem for Linux), with Docker Desktop for the server. Set that up once, then follow the steps below inside WSL.

  1. Install WSL. Open PowerShell as administrator and run wsl --install. Restart when asked; Ubuntu then opens and asks for a Linux username and password.
  2. Install Docker Desktop. In its settings, turn on Start Docker Desktop when you sign in (General) and the integration for Ubuntu (Resources → WSL integration).
  3. Open Ubuntu from the Start menu and run the commands from step 1 there. Keep PaperKiosk in your Linux home folder, not on C: (/mnt/c/...): the installer refuses that, because the keys can't be protected there.
  4. Let screens in. When Windows asks whether Docker may accept connections, allow it for private networks, and make sure your home Wi-Fi is set to Private in Windows. If screens still can't connect, run this in PowerShell as administrator: 
    New-NetFirewallRule -DisplayName PaperKiosk -Direction Inbound -Protocol TCP -LocalPort 8100 -Action Allow -Profile Private
  5. Keep the PC awake. Settings → System → Power: set sleep to Never when plugged in. If the PC sleeps, the screens stop updating.

Good to know on Windows:

  • The address for screens is the PC's own IP on your network; the installer looks it up.
  • A KUAL device over USB shows up as a drive letter. The installer asks for it (like E) and mounts it in WSL; eject it in Windows afterwards.
  • Docker Desktop hides where screens connect from. So screens can't get settings of their own (they all use the main settings), and for Wi-Fi access the installer asks for the device's IP address.
  • A small always-on Linux machine (a Raspberry Pi, a NAS) avoids all of the above, if you have one.

The steps

  1. Download and run the installer

    On the server, in a terminal:

    $ git clone https://github.com/CornillieJ/PaperKiosk.git
$ cd PaperKiosk
$ ./install.sh

    It first checks Docker and Docker Compose and tells you what's missing. It offers to download gum (about 5 MB, checksum verified, stored in .bin/) for arrow-key menus; without it you get plain questions.

    Then choose Automatic (sensible defaults, only the questions it can't answer itself) or Manual (pick the steps, every question asked).

  2. Server settings

    • Port: 8100 by default. Pick another if something already uses it.
    • Address for screens: this server's IP on your home network, like http://192.168.1.10:8100. Give the server a fixed IP in your router (a DHCP reservation) so screens keep finding it.
    • Time zone: taken from the server; used for the clock and quiet hours.
    • Settings password: for the settings page, at least 8 characters. Only a hash is stored.

    It also creates the kiosk key: the private part of the link screens use to pair.

  3. Connect Home Assistant

    The installer looks for Home Assistant itself (on this machine, at homeassistant.local, at the server's IP). If it can't find it, type the address you use in your browser, for example http://192.168.1.20:8123. Home Assistant on the same machine: http://host.docker.internal:8123.

    Then it needs a long-lived access token. Best practice is a separate user without admin rights:

    1. In Home Assistant: Settings → People → Users → Add user. Name it PaperKiosk, set a long password, turn Administrator off and Can only log in from the local network on. No Users tab? Enable Advanced mode in your profile first.
    2. Log in as that user (a private browser window is easiest), open the profile (bottom left) → Security.
    3. Under Long-lived access tokens, choose Create token, name it PaperKiosk, and copy it.
    4. Paste it into the installer. It tests the connection and shows what it found.

    Last question: which room the screen is in. That room's devices show on Home until you pick your own cards.

  4. The screen

    The installer starts the server, then asks what kind of screen you have.

    KUAL device, over USB

    Connect it to the server with a data cable. The installer finds the drive, copies extensions/paperkiosk with your personal kiosk link in it, and ejects the drive.

    KUAL device, over Wi-Fi

    If USBNetwork's SSH already works. The installer adds its own SSH key, copies the extension and can do the next step for you.

    KUAL device, copy it yourself

    The installer prepares data/kindle-extension/paperkiosk. Copy that folder into the device's extensions folder.

    Browser or e-paper dashboard

    You get the kiosk link (and a QR code if qrencode is installed). Nothing to install, and the KUAL steps are skipped.

    Wi-Fi access (optional). For KUAL devices the installer asks whether this server may log in over Wi-Fi (USBNetwork, SSH on Wi-Fi only, with a key that only this server has). That lets it start the kiosk, update it and take screenshots. USBNetwork's SSH also accepts the device's root password, so only use it on a network you trust.

    Browsers and dashboards. Open the link once in a browser and add it to the home screen; the browser remembers it. Dashboards that load a URL can use the link as it is: it works on every request, also without cookies. Pages are about 600 × 750 CSS pixels and scale to the screen.

  5. Start the kiosk

    KUAL devices only. With Wi-Fi access, the installer starts it for you. Otherwise open KUAL → PaperKiosk → Start kiosk on the device. The installer waits until the device connects and confirms it worked.

    Start kiosk opens PaperKiosk full screen, keeps the screen on, and restarts it every night at 4:00 to keep it fresh. Stop kiosk lets the device sleep again.

After installing

  • Settings: open http://your-server:8100/config and log in. Choose up to six cards for Home, add nicknames and icons, pick the pet and home style, set quiet hours. New Home Assistant devices wait under New in Home Assistant until you tick Show.
  • Keep the screen charging; it stays on.
  • After the device restarts, open KUAL → PaperKiosk → Start kiosk again.
  • Locks and garage doors can be locked and closed. Unlocking or opening them is off until you allow it per device in the settings.

Useful commands

Run them in the PaperKiosk folder. ./install.sh on its own shows a menu with most of these.

./install.sh --add-screenAdd another screen, optionally with its own room and cards
./scripts/update.shGet the newest version, rebuild, update KUAL devices it can reach
./scripts/10-configure.sh --new-passwordChange the settings password
./scripts/20-home-assistant.shChange the Home Assistant address or token
./scripts/40-kindle-install.shCopy the KUAL extension to a device again
./scripts/10-configure.sh --new-keyNew kiosk key: un-pairs every screen
./install.sh --yesUnattended install; answers come from environment variables (ADMIN_PASSWORD, HA_URL, HA_TOKEN, SCREEN, ...)

Troubleshooting

"This screen isn't paired"
The screen doesn't have the kiosk link yet. Open the link again, or run step 4 again for KUAL devices.
"I can't reach Home Assistant"
The message underneath says why. Usually the token was removed (run ./scripts/20-home-assistant.sh) or the address doesn't work from inside Docker: use the IP address instead of homeassistant.local.
The device doesn't show up in step 5
Check that it's on the same Wi-Fi and that http://your-server:8100/health opens in another browser (a firewall may block the port).
A device is missing on the screen
It's probably waiting under New in Home Assistant in the settings, or it has no area in Home Assistant.

More in troubleshooting.md.

FAQ

Can you help me jailbreak my Kindle, or put KUAL on it?

No. PaperKiosk starts where KUAL already runs, and this project doesn't explain, provide or support jailbreaking or modifying devices. Questions about that won't be answered here or on GitHub.

If you want to read about it, guides exist online, but that's your own decision and your own risk: it can void warranties, break devices, and isn't legal everywhere. Every other kind of screen works without it: any browser or e-paper dashboard can use the kiosk link.

Which devices does the KUAL extension work on?
It was developed for a 1072 × 1448 e-ink screen with the mesquite web engine (WebKit 534) and firmware 5.x. Other devices running KUAL may behave differently. Which device you use is up to you.
Do I need to know Linux?
A little: you run a few commands in a terminal. The installer checks the rest and explains every question. PaperKiosk needs Docker, so on Home Assistant OS it has to run on another computer: a NAS, a Raspberry Pi, or a Windows PC that stays on (see On Windows).
Can I use it away from home?
Don't forward its port in your router. Use a VPN (WireGuard, Tailscale, ...) if you want to reach it from outside.
Is it safe to put on a wall?

Yes. Anyone standing at the screen can only do what the screen shows: switch the devices on it, change brightness, run the scenes you picked. They can't open the settings (that needs your password, on another device), can't reach anything else in Home Assistant, and can't unlock a door or open the garage unless you allowed that for the device.

Want less on it? Hide devices or whole rooms in the settings. If the screen ever goes missing, run ./scripts/10-configure.sh --new-key: its link stops working, and you re-pair your other screens. More in SECURITY.md.
